# 开发计划与演示脚本

> 这份文档是项目早期的规划稿，保留下来是因为它记录了取舍依据。
> 项目本身的功能与架构，请看根目录的 [README.md](../README.md)。

## 1. 两天工时拆分

按"先闭环、再演示力、最后交付"排序。**任何砍需求，砍演示力，不砍闭环。**

### 1.1 人员分工（2 人可合并 C 到 B）

| 角色 | 职责 |
| --- | --- |
| A · 前端与演示 | 页面、SVG 地图、逐步揭示、图表、演示脚本 |
| B · 后端与 Agent | FastAPI、模拟引擎、六套提示词、JSON 校验、限流 |
| C · 规则与交付 | 规则引擎、冲突判定、测试、部署、材料 |

### 1.2 Day 1 — 打通核心链路（09:00–22:00）

| 时间 | 任务 | 产出 |
| --- | --- | --- |
| 09:00–10:00 | 仓库骨架、前后端脚手架、DeepSeek Key 验证 | 能起服务 |
| 10:00–12:00 | 模拟引擎与数据模型 | 数据能造 |
| 13:00–15:00 | Agent 决策层：提示词、契约校验、降级、限流 | 单角色能出建议 |
| 15:00–17:00 | 规则引擎：资源、路径、冲突 | 能判"行不行" |
| 17:00–18:30 | 调度中心串联 | 后端闭环 |
| 18:30–20:00 | 前端第一屏 | 能看见 |
| 20:00–22:00 | 联调 | **M1** |

**M1 验收**：一条命令或接口跑完"事件 → 六 Agent 建议 → 规则校验 → 方案"，前端能展示。

### 1.3 Day 2 — 演示力与交付（09:00–18:30）

| 时间 | 任务 | 产出 |
| --- | --- | --- |
| 09:00–10:30 | 过程可见：SSE 逐步揭示 | 决策过程可看 |
| 10:30–12:00 | 冲突场景打磨 | 冲突可演示 |
| 13:00–15:00 | 指标、对比、报告 | 有数据说服力 |
| 15:00–16:30 | 部署上线、实测内存 | 可远程访问 |
| 16:30–17:30 | 彩排 + 兜底录屏 | 不怕意外 |
| 17:30–18:30 | 答辩材料 | **M2** |

### 1.4 砍需求顺序（提前定死，避免现场争吵）

1. 先砍指标图表与报告导出（用表格代替）；
2. 再砍决策 Agent（回退路线 A）；
3. 最后才砍模拟居民规模；
4. **永不砍**：一次完整模拟闭环、冲突检测与重分配、过程可见。

## 2. 三分钟演示脚本

1. **0:00–0:20 开场**：一句话说明问题——"六个部门各说各话，LLM 又会编造资源"。
2. **0:20–1:00 跑暴雨场景**：选 Ⅲ 级、1× 人数，开始模拟。指着交互看六角色逐条出方案。
3. **1:00–1:40 讲冲突**：保卫要封 2 号道路，规则引擎判定"会切断唯一通道"，降级为设警戒点。
4. **1:40–2:20 打开决策 Agent**：同一场景跑路线 B，对比表上冲突从 2 降到 0。
5. **2:20–2:50 讲可信度**：无干预对照（91 人危险 / 26 人伤亡）+ 风险覆盖率 94.5%；被驳回的角色带原因重申请。
6. **2:50–3:00 收尾**：规则引擎的硬校验是"AI 说错也拦得住"的保证。
